# Side courier revision — 17 October 2026

This revision supersedes the earlier bottom-opening shelf and Dock picker interaction. The old Dock picker source remains for reference but is no longer installed or shown. There is one reusable courier panel, with mutually exclusive side choices, folder, media preparation and Bin content. A short-lived noninteractive ghost is used only for the menu-bar transition animation.

## Interaction

- Startup shows only the resident courier, never the hub. Empty hover opens its chosen file view after a 350ms dwell. Single-click reveals Close at the top-right and + at the bottom-right. Double-click opens the full app. There is no expand button.
- + opens a native naming dialog directly. Create and pin makes the named parcel the only pinned bag; Cancel leaves the library unchanged. Invalid names do not create a collection. Existing bags and files remain safe. Close/+ sizing remains independent, with the former expand preference retained internally for compatibility.
- The main bag is the only pinned parcel, or the most recent when none is pinned. Drag-hover lasts one second, then shows a small New action below-right, not a second bag icon or a recent-parcel row. Click/drop on New asks for a name and pins the new parcel. A direct drop onto the main bag still appends there.
- File views can open left, right, above or below. The chosen direction is never silently reversed. At display edges the courier moves inward temporarily to make room; the resting saved position is unchanged unless the user drags it. The New action is always below-right, independently of file-view direction. Placement is bounded on small and negative-origin displays.
- Dial opens directly as an upright transparent semicircle anchored to the main icon's center, not in a separate tall folder. Left/right use the corresponding half-circle; above/below rotate that geometry. Cards keep a constant radius and remain upright. Scrolling anywhere in the whole pane loops both ways. At most seven unique cards are constructed, five visible. Small displays use a single-card dial. Grid/List remain glass alternatives. Accessibility adjustment belongs to the dial receiver only. The old scroll and preview-hint strips are gone.
- Files show their registered application icon for documents (Excel/Numbers, TextEdit, etc.), or their native media/folder icon. Dial tiles contain only an icon and name: no white card or copy-button plate. Desktop directions still use the icon-anchored semicircle; only the parked menu-bar dial is a straight horizontal row with the same circular scrolling.
- Hover uses real macOS Quick Look in a separate interactive child panel beside the entire courier surface, never an overlay on its files. The installed generator determines spreadsheet/PDF/document rendering. A native two-axis scroll view supplies a larger preview canvas and visible horizontal/vertical scrollers. Preview scrolling belongs to its own window and cannot rotate the dial. The floating preview replaces on a new hover, waits three seconds after leaving, cancels expiry when entered, and remains while in use; leaving the preview starts a fresh three-second delay. Closing/collapsing, moving, parking or changing parcels releases the preview.
- Preview placement prefers an available horizontal side, shrinks its width when necessary, and temporarily shifts the expanded surface only if neither side otherwise fits. The saved courier anchor is never changed. If even a 192-point-wide preview cannot fit beside the shelf on a very small display at large scale, it is suppressed rather than covering files; native context-menu Quick Look remains available. This constrained-screen case still needs physical acceptance.
- Paste, Copy all, Pack, Settings, pin, delete and parcel name share the top bar. Bin is a direct button; the media/ZIP menu has no redundant New or Bin item. Ready ZIP pickup/share stays in this bar. Search is a third compact row; no bottom footer or reserved preview panel is added. Deletion confirmations and 30-day Bin safety are unchanged.
- Local natural-language search supports type unions (Excel or Numbers), filename terms/quoted phrases, added-date phrases (today/yesterday/last 7 days, ISO dates, ‘on 17th’ meaning this month) and size comparisons such as ‘pdf over 10 MB’. ‘Uploaded’ is interpreted as added to Parcel, never as cloud upload. A filter menu provides file type, size and added date. The resolved ordinal date is displayed, and invalid dates match nothing rather than silently guessing. Courier results stay in the current parcel; the hub also searches across parcel collections. Copy while filtering copies only matching files; Pack explicitly packs the entire parcel.
- Universal interface size is adjustable from 75–150% and scales cards, bags, search, controls, hub and Settings together. Individual icon and Close/+ settings remain. Main Close/+ physical targets remain at least 32 points. Native OS dialogs/menus use macOS's sizing. Panel placement uses scaled physical bounds rather than clipping a visually enlarged logical panel.
- After 30 seconds of courier inactivity it parks in the menu bar, excluding ongoing operations, confirmations, menus and drag-out. Settings provides an editable 5–3600-second timeout and Never. Activity is timestamped without recreating a timer on every mouse move. Any incoming file drag restores the courier to its saved location. A deliberate horizontal or vertical shake with no held button also restores it, with amplitude/reversal thresholds and a cooldown; ordinary motion/jitter does not. The event-driven mouse monitor adds no idle polling loop.
- Right-click the courier for native Share, Copy ZIP to WhatsApp, Copy ZIP, New, Open files/hub, Settings, Hide and Quit. Sharing prepares a real ZIP locally first. WhatsApp is opened with the ZIP copied for the user to choose a chat and paste; Parcel never selects a recipient or silently sends private files.
- Right-button dragging the courier requests a ZIP and starts native file dragging only while the same button is still held. Releasing before packing finishes cancels pickup, not the safe local package. A destination must accept file drops; Parcel cannot force arbitrary apps or empty screen space to receive/send files. Ordinary left dragging still repositions the courier. Archive pickup uses built-in ZIP without changing the user's normal format/save preferences.
- Finder/system integration uses the native macOS Services contract: selected files/folders → Services → Send to Parcels. It accepts file URLs/legacy filenames, never remote web URLs, and ingests into the main bag without opening the hub. macOS controls Services availability and enablement; this is not an injected universal top-level context menu or an unsigned Finder Sync extension.
- The menu-bar icon toggles courier hide/return. The same art/count travels both ways with a short ghost transition; rapid reversals close obsolete ghosts and generation checks prevent stale completion changes. Reduce Motion skips travel. Menu-bar hover/drop uses the same primary destination.
- Native WindowServer dragging remains in use. Hover/preview/dismiss work cancels or pauses during movement, menus, confirmation, receipt and packing. Single-pin migration, original files, auto-clear thresholds and cache cleanup rules are unchanged.
- Reference folder papers, actual receipt catch, fan springs and partial cord/full successful bow remain. Duplicates and failed/cancelled jobs never fake receipt or completed ribbon. No perpetual idle animation is added.

## Hem reference assets

The user supplied the downloaded `Parcels-All-Files.zip` after the Gmail connector's unsupported-ZIP limitation. All three HQ videos were sampled at exact timestamps with AVFoundation, and the shot sheet, icon source and animation compositions were read. The archive's original icon is code-drawn, not a transparent PNG; its dark tabbed shell, paper layers and glass-front geometry were reconstructed natively. Horizontal/vertical cord and bow paths replace the provisional zipper. The supplied screenshots were inspected but not cropped into runtime artwork. No ZIP scripts/dependencies were run, and no screenshot phone/Pinterest chrome is shipped. See [Hem reference study](HEM-REFERENCE-STUDY.md) for source details, timing and deliberate product adaptations.

Settings is an explicitly created AppKit window, not an automatically presented SwiftUI Settings scene. A non-inserted `MenuBarExtra` supplies the app command scene without adding a second status item. This supports the existing macOS 14 minimum and prevents automatic Settings restoration on launch.

## Media preparation

The folder's Prepare action supports both images and videos without opening the main app. Video preparation is also available in the main app's Parcel menu. Image format, maximum dimensions, quality, metadata removal and white-background consent remain available.

Video preparation creates new MP4 or MOV files with native AVFoundation, using Small, Balanced or High quality and a maximum edge of 480, 720, 1280, 1920 or 3840 pixels. It preserves orientation and does not upscale. Output is up to 30 fps; a lower-quality Apple preset may further reduce resolution. The native exporter retains compatible audio. Codec/HDR compatibility depends on macOS; unsupported inputs produce an error rather than replacing the source. Exact target bytes and smaller output are not guaranteed for already-efficient inputs.

Each source is coordinated into a temporary snapshot before processing. Export occurs away from UI rendering, with cancellation checks during copying and a 100ms native-export cancellation monitor. Failed/cancelled partial output is removed; completed outputs are attached only to the captured parcel/item identities. Originals are not modified. This is a size/quality preparation tool, not a timeline or trimming editor.

## Watched folders

Settings supports up to eight explicitly selected folders and a destination parcel for each. Existing top-level entries form the baseline; only later arrivals are imported. The watcher uses filesystem events, debounces changes and checks unchanged size/date over two observations plus a two-second quiet period. Partial download extensions, hidden files and symlinks are ignored. A final renamed download becomes eligible. A quiet period is a heuristic, not a guarantee that every third-party writer has finished.

Rules and read-only security bookmarks persist locally. Busy/reception periods defer delivery; a missing/Bin destination stops that scan with a Settings message rather than creating or redirecting a parcel. Removing a rule stops watching without removing parcel entries or originals. Names that disappear are removed from the baseline so a later arrival can be recognized. Parcel's own cache cannot be watched, and known prepared/exported outputs are skipped to avoid import feedback loops. Background delivery does not invalidate an unrelated selected parcel's archive.

The native watch regression also checks generated-output exclusion through canonical paths: bookmark resolution can turn `/var` into `/private/var`, and those aliases must not cause Parcel to reimport its own exported ZIP. Watch failures stop that scan and retain a diagnostic instead of repeatedly consuming idle CPU.

No cloud upload, custom scripts, AI naming, desktop widgets or external account integrations were enabled. These remain separate product/safety decisions, not implied by researching every advertised competitor feature.

## Research

Rechecked Dropover's [official feature overview](https://dropoverapp.com/), [observed-folder introduction](https://dropoverapp.com/whats-new/4.4.0), [folder browsing](https://dropoverapp.com/whats-new/4.9.0) and [5.3 inline action changes](https://dropoverapp.com/whats-new/5.3.0). Its useful local patterns include direct manipulation of individual files, compact shelf detail views, contextual actions and observed-folder intake. Its 5.3 inline action UI reinforces keeping work in the shelf rather than forcing modal restarts.

The site's actual video elements were inspected in the in-app browser. The [official intro video](https://dropover.s3.eu-central-1.amazonaws.com/videos/ventura/dropover_intro.mp4) loaded and played (9.35 seconds); visual sampling showed multi-file drag pickup and an overlaid collection. The [individual-file demo](https://dropover.s3.eu-central-1.amazonaws.com/videos/monterey/manage-individual-drags.mp4) loaded through its final frame (7.23 seconds), showing grid detail with file-specific actions. These were visual spot-checks, not a hands-on installation, exhaustive video analysis or performance benchmark. The new interaction follows this user's specification rather than copying Dropover's multiple shelf/detail surfaces.
